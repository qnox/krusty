A Kotlin compiler
written in Rust

krusty is a drop-in replacement for kotlinc on the JVM: the same command-line flags in, and .class files that are byte-for-byte identical to kotlinc's out, from a single native binary.

Download Source on GitHub

Use it like kotlinc

krusty src/ -d out/                          # compile a source tree to a class dir
krusty src/ -d mylib.jar -module-name mylib  # ... or to a library .jar
krusty -cp deps.jar:classes/ App.kt -d out/  # with a classpath
krusty -version

Prebuilt binaries for Linux, macOS and Windows (x86_64 and arm64) are attached to every release. To build from source: cargo build --release -p krusty-cli.

Why krusty

Byte-for-byte identical

Output is checked against the real kotlinc: class files, @kotlin.Metadata and .kotlin_module, plus Kotlin and Java consumers compiled against it.

Tested on Kotlin's own suite

Every build runs JetBrains' codegen/box corpus on the JVM. The badge above shows the current pass rate.

Memory-lean

Compact, index-based compiler data and a file-at-a-time backend, so more builds fit on one CI runner.

Native binary

Written in Rust with its own class-file writer and no bytecode library. The compiler runs natively, with no JVM start-up or warm-up.

Serialization and KSP

kotlinx.serialization runs as a native compiler pass, and KSP processors run through a code-generation host.

Kotlin 2.4

Matches the current Kotlin 2.4 releases; the badge above lists the supported versions. Choose which one to match with KRUSTY_LANGUAGE_VERSION.

Language server and Zed

krusty-lsp is a Kotlin language server backed by the same compiler: diagnostics, completion, hover, go-to-definition, find references, rename and more. It reads Gradle, Maven and BSP project models. A Zed extension ships with every release.
