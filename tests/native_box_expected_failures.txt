# Corpus cases the native lane ACCEPTS and runs WRONG today, each a known defect outside the native
# backend that the JVM lane fails on as well. Format: <path relative to the box corpus root><TAB><reason>.
# A case not listed here that fails, or a case listed here that passes, fails the test — so this list
# can only shrink honestly. See tests/kotlin_box_native_conformance.rs.
casts/kt83324.kt	the frontend smart-casts a `var` that the loop reassigns, so the IR carries a cast to the first assignment's class; the cast fails at runtime (a frontend defect, not a lowering one)
intrinsics/prefixIncDec.kt	`++prop` on a property with custom accessors reads it once where kotlinc reads it twice, so the accessor side effect is counted 2 instead of 3 — krusty's JVM backend prints the identical "fail in prefix increment: 2 != 3", so this is common lowering's, not the generator's
statics/incInObject.kt	`r2++`/`++r2` on an object property with a custom getter counts three getter calls where kotlinc counts four — krusty's JVM backend prints the identical "fail 2:  3 getR2getR2getR2", so this is common lowering's increment shape, not the generator's
statics/incInClassObject.kt	same increment shape as statics/incInObject.kt; krusty's JVM backend prints the identical failure
contextParameters/classMemberAndTopLevelWithContext.kt	a context parameter picks the wrong receiver — krusty's JVM backend prints the identical "NOK", so this is the frontend's, not the generator's
extensionFunctions/executionOrder.kt	an extension call evaluates its receiver and function in the wrong order — krusty's JVM backend prints the identical "fail getReceiver->getFun()->End"
multiDecl/nameBasedDestructuringUnderscoreWithRenaming.kt	a name-based destructuring with a renamed underscore binds the wrong component — krusty's JVM backend prints the identical "FAIL: 0", so this is the frontend's
super/superConstructor/kt13846.kt	a reference to an object's member, used as a superclass constructor argument, binds `this` as its receiver instead of the singleton — krusty's JVM backend emits bytecode the verifier rejects for exactly that ("uninitializedThis is not assignable"), so the bound receiver is common lowering's. Natively there is no verifier, so the same wrong IR crashes instead of failing to load
inference/whenAtAssignment.kt	a `when` assigned to an interface-typed `val` takes the type of one branch, so the other branch's value is cast to it — krusty's JVM backend throws the identical `ClassCastException: class A cannot be cast to class B`, and the case itself records kotlinc's K2 failing the same way (KT-77008)
inference/whenAtAssignmentWithSmartCast.kt	same `when`-assignment shape as inference/whenAtAssignment.kt, with a smart cast; krusty's JVM backend throws the identical `ClassCastException`
privateConstructors/inner.kt	`this@Outer` inside an `inner` class that also EXTENDS its outer resolves to `this` rather than the enclosing instance, so `this.s + this@Outer.s` answers "OO" instead of "OK" — krusty's JVM backend prints the identical "OO", so the receiver is the frontend's
closures/captureInSuperConstructorCall/properValueCapturedByClosure2.kt	a lambda capturing the enclosing instance inside a SUPERCLASS constructor argument binds the wrong receiver — krusty's JVM backend emits bytecode the verifier rejects for exactly that ("Type uninitializedThis ... is not assignable"), the same shape as super/superConstructor/kt13846.kt; natively there is no verifier, so the wrong IR answers with the function object instead of failing to load
defaultArguments/function/kt36188.kt	a class inheriting the same defaulted method from two interfaces takes the wrong interface's default ("Fail" instead of "OK") — krusty's JVM backend prints the identical "Fail", so the choice is common lowering's
defaultArguments/convention/incWithDefaultInGetter.kt	`++` on a property whose getter takes a defaulted argument counts the accessor calls wrongly — krusty's JVM backend prints the identical "fail 2: anone1", the same increment shape as intrinsics/prefixIncDec.kt
defaultArguments/function/kt36188_2.kt	same inherited-default choice as defaultArguments/function/kt36188.kt, through one more interface; krusty's JVM backend prints the identical "Fail"
secondaryConstructors/accessToCompanion.kt	a companion member read in a secondary constructor's DELEGATION argument binds `this` as its receiver instead of the companion — krusty's JVM backend emits bytecode the verifier rejects for exactly that ("Type uninitializedThis ... is not assignable to 'A$Companion'"), the same shape as super/superConstructor/kt13846.kt
evaluate/intrinsicConst/enumNameWithInit.kt	`EnumClass.OK.name` under +IntrinsicConstEvaluation is meant to fold at compile time, so the enum's `init` never runs; krusty evaluates it at run time and the `init` sets "Fail" — krusty's JVM backend prints the identical "Fail", so the folding is the frontend's to do
sealed/kt49752.kt	a `when` over a sealed hierarchy casts a branch's value to the wrong subclass — krusty's JVM backend throws the identical `ClassCastException: BaseTerminal$Success cannot be cast to CountingInterpreter$Intermediary$KeepCounting`, so this is the frontend's smart cast, not the generator's
classes/selfcreate.kt	an anonymous object passes its enclosing instance's `b` to its own superclass constructor; krusty's JVM backend rejects the same program with `VerifyError: Bad type on operand stack`
closures/captureInSuperConstructorCall/localCapturedInAnonymousObjectInLocalClass.kt	an anonymous object inside a local class passes a captured local to its superclass constructor; krusty's JVM backend rejects the same program with `VerifyError: Bad type on operand stack`
closures/captureInSuperConstructorCall/localCapturedInAnonymousObjectInLocalClass2.kt	same shape as localCapturedInAnonymousObjectInLocalClass.kt with a second capture; krusty's JVM backend rejects the same program with `VerifyError: Bad type on operand stack`
inference/whenAtAssignmentWithSmartCastInsideCapturedLambda.kt	same `when`-assignment shape as inference/whenAtAssignment.kt, inside a captured lambda; krusty's JVM backend throws the identical `ClassCastException: class A cannot be cast to class B`
localClasses/innerClassInLocalClass.kt	an `inner` class of a local class reaches `this@A` through two enclosing instances; krusty's JVM backend rejects the same program with `VerifyError: Bad type on operand stack`
objects/kt3684.kt	`n` inside an anonymous subclass of `X` names the ENCLOSING `X` instance's private field, not the anonymous instance's own; both backends read the anonymous instance's, so krusty's JVM backend prints the identical `inner`
properties/fieldInsideField.kt	a property's `get() = field + object : Your() { override val your = "K" get() = field }.foo()` — the inner `field` binds to the outer property in both backends, so krusty's JVM backend fails the same program with `StackOverflowError`
super/kt4173_2.kt	a lambda writing an enclosing `var` is passed through two nested anonymous objects' superclass constructors; krusty's JVM backend rejects the same program with `VerifyError: Bad type on operand stack`
super/kt4982.kt	an abstract class's `init` calls an overridden method that writes a captured `var`, and the anonymous subclass's capture field is written AFTER the superclass constructor runs — krusty's JVM backend throws `NullPointerException: Cannot assign field "element" because "this.result" is null` on the same program, so the store order is common lowering's
smartCasts/invokeRecieverSmartcastK2.kt	`(a as String)(a)` selects `String.invoke(Any)` where kotlinc selects `Any.invoke(String)` — krusty's JVM backend prints the identical "FAIL: implicitReceiverCast(): String.invoke(Any)", so the selection is the frontend's
smartCasts/kt44804.kt	a `var` initialized from a `LineNumberNode` keeps that smart cast across the loop's own reassignment, so a `when` branch casts a `LabelNode` to it — the same shape as casts/kt83324.kt. Reduced to one file, krusty's JVM backend throws the identical `ClassCastException: class Label cannot be cast to class Line`; on the corpus case itself it does not get that far, failing to load with `ClassFormatError: Invalid pc in LineNumberTable`
